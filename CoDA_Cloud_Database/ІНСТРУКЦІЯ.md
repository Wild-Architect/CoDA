# Оновлення бази CoDA через GitHub

## Звідки беруться файли

Окрема папка `database` більше не використовується. Генератор бере актуальну локальну базу безпосередньо з програми:

- `..\data\dbn_catalog.xlsx` — каталог ДБН;
- `..\building_codes\` — PDF нормативних документів.

У ZIP ці файли автоматично потрапляють у форматі, який очікує оновлювач: `dbn_catalog.xlsx` і `building_codes\...`.

Службові файли розташовані тут:

- `manifest.json` — локальна копія актуального маніфесту GitHub;
- `releases\` — створені ZIP-пакети;
- `СТВОРИТИ_ОНОВЛЕННЯ.bat` — створення наступного інкрементального пакета;
- `ДОДАТИ_ПОСИЛАННЯ.bat` — додавання URL опублікованого ZIP до маніфесту.

Репозиторій бази: <https://github.com/Wild-Architect/CoDA-Database>
Маніфест: <https://raw.githubusercontent.com/Wild-Architect/CoDA-Database/main/manifest.json>

## Підготовка оновлення

1. Збережіть резервну копію каталогу та PDF, які збираєтеся змінювати.
2. Відредагуйте `..\data\dbn_catalog.xlsx`.
3. На аркуші `Налаштування` запишіть у `B2` дату у форматі `РРРР-ММ-ДД`, а в `B3` — нову унікальну версію.
4. Додайте, замініть або видаліть PDF у `..\building_codes\`.
5. Перевірте, що значення стовпця `Файл ДБН` відповідають назвам PDF.
6. Закрийте Excel.
7. Переконайтеся, що поруч із цією інструкцією лежить актуальний `manifest.json` з GitHub. Для першого майбутнього оновлення його `latestVersion` має бути `2026.08.09.2`.
8. Запустіть `СТВОРИТИ_ОНОВЛЕННЯ.bat` і введіть значення з клітинок `B3` та `B2`.
9. Готовий пакет `CoDA-update-ВЕРСІЯ.zip` з'явиться в `releases`.

Скрипт порівнює поточні файли з `manifest.json`. До ZIP потрапляють лише змінені й додані файли, а перелік видалених записується до `update.json`.

## Публікація

1. Створіть GitHub Release з тегом `db-ВЕРСІЯ`.
2. Додайте створений ZIP і опублікуйте Release.
3. Запустіть `ДОДАТИ_ПОСИЛАННЯ.bat`, введіть версію та пряме посилання на ZIP.
4. Лише після публікації ZIP замініть `manifest.json` у репозиторії його новою локальною версією.
5. Перевірте оновлення кнопкою в CoDA на тестовому комп'ютері.

## Важливі правила

- Спочатку публікуйте ZIP, потім маніфест.
- Не використовуйте одну версію двічі.
- Не змінюйте вже опубліковані ZIP-пакети.
- Не створюйте пакет, якщо локальний `manifest.json` не відповідає версії на GitHub.
- Не додавайте PDF або ZIP безпосередньо до Git-репозиторію бази.
- Перш ніж публікувати, можна перевірити джерело командою:

  ```powershell
  powershell -NoProfile -File .\tools\Build-CoDAUpdate.ps1 -Mode Verify
  ```

Рекомендований формат версії: `2026.09.01`, а для кількох випусків за день — `2026.09.01.1`, `2026.09.01.2` тощо.
